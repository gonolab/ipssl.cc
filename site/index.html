Write the address into the name.

Write the address with dashes so it fits in one label: dots for IPv4, colons for IPv6. Anything in front of it is yours to choose. Nothing to register: every name below works now.

Rules

  • When a name holds more than one address, the rightmost one, closest to the zone, wins.
  • Numbers with leading zeros, such as 010, are rejected, so nobody has to guess whether they are octal.
  • An AAAA query for an IPv4 name, or the other way round, gets an empty answer, not NXDOMAIN.
  • A TXT query for ip.ipssl.cc returns the address the query came from, usually your resolver.

Real SSL certificates, for public and private addresses.

The certificate comes from Let's Encrypt or any other ACME CA and is issued to you: the private key never leaves your machine. How the CA checks the name depends on where the address lives.

Public address

Your address

On the server itself

The name resolves to your server, so the CA connects to it to check. Run one command on that server. HTTP-01 or TLS-ALPN-01

$ sudo certbot certonly --standalone \    -d 203-0-113-10.ipssl.cc
$ acme.sh --issue --standalone \    -d 203-0-113-10.ipssl.cc
# Caddyfile203-0-113-10.ipssl.cc {    reverse_proxy localhost:8080}

From any machine, through DNS

A CA cannot reach 192.168.1.10, so your ACME client posts the check to https://ipssl.cc/acme and ipssl.cc answers it in DNS. DNS-01

$ curl -fsSLO https://ipssl.cc/acme/ipssl-certbot-hook.sh$ sudo certbot certonly --manual --preferred-challenges dns \    --manual-auth-hook "sh $PWD/ipssl-certbot-hook.sh present" \    --manual-cleanup-hook "sh $PWD/ipssl-certbot-hook.sh cleanup" \    -d 192-168-1-10.ipssl.cc

Run it on any machine with internet access.

Any CA
The zone publishes no CAA record, so Let's Encrypt, ZeroSSL, Google Trust Services and others can all issue.
Encrypted, not identified
A private address exists on countless networks, so anyone can get a certificate for the same name. It encrypts the connection; it does not prove whose machine you reached.
One shared limit
Every name under ipssl.cc counts toward Let's Encrypt's limit for the domain. Keep a certificate until it is due for renewal, or use another CA.

Questions

Something missing? Ask in the issue tracker.

Can an AI agent set this up for me?

Yes. Give it the prompt at the top of this page. llms.txt tells it how to pick the name, which certificate path fits the address, and the exact commands.

Why doesn't a private address resolve on my network?

Many routers (OpenWrt, pfSense, dnsmasq, Fritz!Box and others) have DNS rebinding protection, which drops answers that point to private addresses. Allowlist ipssl.cc there, or use a public resolver.

Can I download a wildcard certificate for ipssl.cc?

No. Publishing a private key breaks the CA's subscriber agreement, and anyone holding the key could revoke the certificate. Get your own certificate instead; it takes one command.

Why isn't ipssl.cc on the Public Suffix List?

The list excludes services that resolve an IP address written in a hostname to that address: the same IP can belong to different people over time, so it does not show stable control of a name. DNS resolution does not depend on the list.

How do I see where my DNS queries come from?

Run dig +short TXT ip.ipssl.cc. The answer is the address the query reached us from, which is usually your recursive resolver.

Can I run this for my own domain?

Yes. The server is open source under the MIT license, and the install script below sets it up on any Linux server. The README covers the config and the registrar setup.

How do I report abuse?

Email abuse@ipssl.cc or open an issue on GitHub with the name and what it is used for. The server has a blocklist, so names used for abuse can stop resolving.
